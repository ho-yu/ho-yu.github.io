## 2. 📦 패딩과 길이 제한을 사용하는 이유

> ❓ "여러문장을 한번에 처리할 때, 패딩과 길이제한을 자주 사용하는 이유가 뭔지도 알려줘."

한 번에 처리하는 입력 묶음을 **배치(batch)** 라고 합니다. 리뷰 3개를 한 번에 처리하면 배치
크기가 3입니다. 패딩과 잘라내기는 서로 다른 문제를 해결합니다.

| 작업 | 하는 일 | 목적 |
| --- | --- | --- |
| **패딩(Padding)** | 짧은 입력에 PAD 토큰을 추가 | 같은 배치의 입력 길이를 맞춤 |
| **잘라내기(Truncation)** | 설정한 길이를 넘는 입력을 자름 | 입력 한도와 계산량을 관리 |

### 패딩과 `attention_mask`

토큰 길이가 3, 5, 2인 리뷰를 하나의 일반적인 텐서로 묶으려면, 각 행의 길이를 같게 만듭니다.
가장 긴 리뷰에 맞추면 모두 5칸이 됩니다.

![리뷰 A·B·C의 input_ids가 각각 토큰 3·5·2개이고 부족한 자리를 PAD로 채워 [3, 5] 모양이 되며, 아래 attention_mask에서 입력 위치는 1, 패딩 위치는 0으로 표시되는 그림](/assets/img/posts/padding-truncation-and-shape/padding-and-mask.svg){: w="720" h="362" }

모양이 일정하면 여러 문장을 묶어서 GPU 등의 장치에서 계산하기 편해집니다. 패딩은 문장의 의미를
보충하는 것이 아니라 배열에 필요한 자리를 채우는 작업입니다.

| 값 | 이 배치 예시에서의 의미 |
| --- | --- |
| `1` | 실제 입력 위치. 모델에 필요한 특수 토큰도 포함 |
| `0` | 패딩 위치. 어텐션에서 참조하지 않도록 표시 |

> ⚠️ 이 값은 단어 중요도 점수가 아닙니다. 또한 마스크를 사용해도 일반적인 밀집 텐서 계산에서
> 패딩의 메모리·연산 비용이 모두 사라지는 것은 아닙니다.
{: .prompt-warning }

### 길이 제한 — 너무 긴 입력의 부담을 관리한다

1. **모델의 입력 한도** — 모델이 지원하는 최대 길이를 넘지 않도록 합니다.
2. **계산량과 메모리** — 긴 입력일수록 처리 부담이 커집니다.
3. **배치의 패딩 낭비** — 아주 긴 리뷰 하나 때문에 나머지 짧은 리뷰도 길게 패딩되는 상황을
   줄입니다.

예를 들어 길이가 20, 30, 1,000인 리뷰를 최장 길이에 맞추면 모두 1,000칸이 됩니다. 앞의 두
리뷰는 대부분이 패딩입니다.

일반적인 전체 셀프 어텐션에서는 길이가 `L`일 때 토큰 간 점수의 수가 `L²`에 비례합니다.

| 토큰 길이 `L` | 토큰 간 점수의 수 `L²` |
| --- | --- |
| 128 | 16,384 |
| 256 | 65,536 |
| 512 | 262,144 |

길이가 2배면 이 부분의 토큰 쌍 수는 4배가 됩니다. 모델 전체 실행 시간이 반드시 정확히 4배가
된다는 뜻은 아닙니다.

> ⚠️ 다만 잘라내면 정보가 사라질 수 있습니다. 리뷰 끝의 "그런데 며칠 쓰니 고장 났어요"가
> 잘리면 감성 분류에 필요한 단서를 잃습니다.
{: .prompt-warning }

길이는 실제 토큰 길이 분포, 중요한 내용의 위치, 모델 한도와 메모리를 고려해 정합니다. 긴 내용을
보존해야 하면 여러 구간으로 나누어 처리할 수도 있습니다.

## 3. 📐 왜 배열의 모양을 맞춰야 하는가?

> ❓ "왜 배열의 모양을 맞춰야 하고, 어떤 규칙때문에 배열을 맞추는거야?"

여기에는 텐서의 모양에 관한 조건과 행렬 연산의 차원 조건이 있습니다. 서로 연결되지만 같은
조건은 아닙니다.

### 조건 A — 일반적인 밀집 텐서는 각 축의 크기가 일정하다

머신러닝에서 텐서는 숫자를 여러 차원의 배열로 담는 자료구조라고 이해하면 됩니다. 파이썬
리스트는 길이가 다른 리스트들을 담을 수 있습니다.

```python
reviews = [
    [11, 12, 13],
    [21, 22, 23, 24, 25],
    [31, 32]
]
```

그러나 이 데이터를 하나의 일반적인 2차원 텐서로 만들려면 모양을 `[행 수, 열 수]`로 표현할 수
있어야 합니다. 행은 3개이지만, 열은 3개·5개·2개로 다릅니다. 패딩으로 모두 5칸으로 맞추면
`[3, 5]`라는 하나의 모양이 정해집니다.

> 💡 자연어의 규칙이 아니라 **여러 입력을 같은 텐서에 담는 방식**에서 오는 조건입니다.
{: .prompt-info }

### 조건 B — 행렬 곱셈에서는 곱하는 두 차원이 맞아야 한다

```text
(m, n) @ (n, p) → (m, p)
```

앞 행렬의 열 수 `n`과 뒤 행렬의 행 수 `n`이 같아야 합니다. 예를 들어 임베딩 결과가 `[3, 5, 4]`
이고 가중치가 `[4, 8]`이면, 각 토큰의 4차원 벡터를 8차원 벡터로 변환할 수 있습니다. 결과는
`[3, 5, 8]`입니다.

| 구분 | 이 예시에서 맞추는 것 | 이유 |
| --- | --- | --- |
| 패딩 | 각 샘플의 토큰 길이를 5로 통일 | 하나의 배치 텐서로 묶기 위해 |
| 행렬 곱셈 | 임베딩의 마지막 차원 4와 가중치의 첫 차원 4 | 벡터에 가중치 행렬을 곱하기 위해 |

문장 길이를 임베딩 차원이나 가중치 차원과 같게 만들 필요는 없습니다. 이 예시에서도 토큰 길이는
5이고 임베딩 차원은 4입니다.

문장을 하나씩 처리한다면 `[1, 3]`, `[1, 5]`, `[1, 2]`처럼 호출마다 길이가 달라도 됩니다. 길이가
다른 입력을 처리하는 특수한 구현도 있지만, 이 노트에서는 일반적인 밀집 배치를 기준으로
설명합니다.

## 4. 🔢 shape 읽기와 임베딩

> ❓ "위 작업이 shape를 맞추는 작업인거지?"

맞습니다. 패딩은 배치로 묶을 입력들의 shape를 맞추는 방법입니다. shape는 각 축의 크기를
순서대로 나타낸 정보입니다. 축(axis)은 데이터를 바라보는 방향 또는 구분 기준이라고 이해하면
됩니다.

> ❓ "input_ids [4, 12]의 두 축은 무엇인가요?"

| 축 | 값 | 의미 |
| --- | --- | --- |
| 첫 번째 축 | 4 | 배치의 입력 샘플 수 |
| 두 번째 축 | 12 | 각 샘플의 최종 토큰 길이 |

리뷰 한 개를 샘플 하나로 넣었다면 "리뷰 4개, 각 12칸"입니다. 샘플 하나가 문장 쌍으로 구성될
수도 있으므로 문장 수보다 **샘플 수**라는 표현이 더 정확합니다.

`12`에는 추가된 특수 토큰과 패딩도 포함됩니다. 원래 길이가 모두 12였다면 패딩 없이도 같은
shape가 나옵니다.

> ⚠️ `input_ids`의 **값**이 `[4, 12]`인 것과 **shape**가 `[4, 12]`인 것은 다릅니다. 전자는 ID
> 두 개이고, 후자는 배열 크기를 설명합니다.
{: .prompt-warning }

### 임베딩을 거치면 축이 하나 추가된다

![왼쪽은 샘플 A·B·C 3개 × 토큰 5칸의 input_ids [3, 5], 오른쪽은 그중 A 샘플 하나를 확대해 각 토큰이 d1부터 d4까지 4차원 벡터로 바뀐 모습이며 전체 결과가 [3, 5, 4]가 되는 그림](/assets/img/posts/padding-truncation-and-shape/embedding-adds-axis.svg){: w="720" h="330" }

| 데이터 | shape | 해석 |
| --- | --- | --- |
| `input_ids` | `[B, L]` | 샘플 B개 × 토큰 L칸 |
| `attention_mask` | `[B, L]` | 각 토큰 위치와 대응되는 마스크 |
| 임베딩 결과 | `[B, L, D]` | 각 토큰을 D차원 벡터로 표현 |

예를 들어 `input_ids`가 `[4, 12]`이고 임베딩 차원이 768이면, 임베딩 결과는 `[4, 12, 768]`
입니다.

### `padding`과 `reshape`는 서로 다른 작업이다

| 작업 | 무엇을 바꾸는가? | 원소 수 |
| --- | --- | --- |
| 패딩 | PAD 값을 추가해 길이를 맞춤 | 추가한 만큼 증가 |
| 잘라내기 | 일부 토큰을 제거해 길이를 제한 | 잘라낸 만큼 감소 |
| `reshape` | 기존 원소를 다른 모양으로 해석 | 유지 |

예를 들어 원소 6개는 `[2, 3]`에서 `[3, 2]`로 reshape할 수 있습니다. 하지만 길이가 다른 문장들을
올바르게 패딩하는 작업을 reshape만으로 대신할 수는 없습니다.

전체 데이터셋의 모든 배치를 같은 길이로 맞출 필요는 없습니다. 같은 텐서로 묶는 입력끼리 맞추면
되므로, 이번 배치는 `[4, 12]`, 다음 배치는 `[4, 20]`이어도 모델이 지원하는 범위 안에서 처리할
수 있습니다.

## 5. 🧪 코드의 패딩·길이 옵션 연결하기

```python
texts = [
    "Good product.",
    "This product is very easy to use."
]

batch = tokenizer(
    texts,
    padding=True,
    truncation=True,
    max_length=128,
    return_tensors="pt"
)
```

| 설정 | 하는 일 |
| --- | --- |
| `texts` | 문자열 리스트를 배치로 전달 |
| `padding=True` | 처리된 입력 중 가장 긴 길이에 맞춰 패딩 |
| `truncation=True` | 지정한 최대 길이를 넘으면 잘라냄 |
| `max_length=128` | 여기서는 특수 토큰을 포함해 최대 128토큰으로 제한 |
| `return_tensors="pt"` | 결과를 PyTorch 텐서로 반환 |

길이 관점에서는 **길이 제한을 적용한 뒤, 같은 배치에서 가장 긴 입력에 맞춘다**고 이해하면
됩니다. 다음 표의 원래 길이는 특수 토큰까지 포함한 길이입니다.

| 원래 길이 | 제한 적용 후 | 패딩 후 |
| --- | --- | --- |
| 20, 70, 200 | 20, 70, 128 | 128, 128, 128 |
| 20, 50, 70 | 20, 50, 70 | 70, 70, 70 |

> ⚠️ `padding=True`와 `max_length=128`을 함께 쓴다고 무조건 128칸으로 채우지는 않습니다. 항상
> 128칸으로 맞추려면 `padding="max_length"`를 사용합니다. `max_length`만 지정하고 잘라내기를
> 켜지 않으면, 긴 입력이 자동으로 잘리는 것도 아닙니다.
{: .prompt-warning }

## 6. 🧯 `token_type_ids`가 없는 모델도 처리하는 방법

> ❓ "token_type_ids가 없는 모델에서도 코드가 동작하게 하려면 어떻게 해야 하나요?"

특정 키가 항상 있다고 가정하지 않으면 됩니다. 반환된 입력과 shape를 확인할 때는 실제로 존재하는
키를 순회합니다.

```python
for key, value in batch.items():
    print(key, value.shape)
```

`items()`는 딕셔너리의 키와 값을 한 쌍씩 가져옵니다. 특정 값이 필요할 때는 존재 여부부터
확인합니다.

```python
if "token_type_ids" in batch:
    print(batch["token_type_ids"])
```

모델과 토크나이저가 맞고 `batch`에 모델이 받는 입력만 들어 있다면, 다음처럼 전달할 수 있습니다.

```python
outputs = model(**batch)
```

`**batch`는 딕셔너리 항목을 이름 있는 인자로 풀어 전달합니다. `batch`에 `input_ids`와
`attention_mask`만 있다면 다음 호출과 같습니다.

```python
outputs = model(
    input_ids=batch["input_ids"],
    attention_mask=batch["attention_mask"]
)
```

없는 `token_type_ids`를 임의로 만들어 추가할 필요는 없습니다.

> ⚠️ 단, `**batch`가 모델이 받지 않는 키까지 알아서 제거해 주지는 않으므로, 분석용 부가정보를
> 넣었다면 모델 입력과 구분해야 합니다.
{: .prompt-warning }

## 7. ✅ 내가 작성한 답변과 정확한 표현

질문 순서대로 직접 작성한 답변 중 이 글에 해당하는 것입니다.

1. 문장 4개와 padding 후 길이 12입니다.
2. 반환된 key를 순회하거나 `if "token_type_ids" in batch`로 조건 처리합니다.

두 답변 모두 핵심을 이해한 답입니다. 복습할 때는 다음처럼 표현을 다듬어 기억하면 정확합니다.

| 항목 | 기억할 답변 |
| --- | --- |
| `[4, 12]`의 축 | 배치의 입력 샘플 4개, 샘플마다 최종 토큰 길이 12. 패딩이 있었다고 단정할 수는 없음 |
| 선택적인 키 처리 | 실제 반환된 키를 순회하거나 존재 여부를 확인. 호환되는 모델에는 모델 입력만 담은 batch를 `**batch`로 전달 가능 |

## 8. 🧠 핵심 기억 카드

<details markdown="1">
<summary><strong>펼쳐서 확인</strong></summary>

- **batch** : 한 번에 처리하는 입력 묶음 — 리뷰 3개면 배치 크기 3
- **패딩** : 짧은 입력에 PAD 추가 → 같은 배치의 길이를 맞춤
- **잘라내기** : 설정 길이를 넘는 입력을 자름 → 입력 한도와 계산량 관리
- **`attention_mask`** : `1`은 입력 위치(특수 토큰 포함), `0`은 패딩 위치 — 중요도 점수가 아니다
- **길이 제한 이유** : 모델 입력 한도 / 계산량·메모리 / 배치의 패딩 낭비
- **`L²`** : 128→16,384, 256→65,536, 512→262,144 — 길이 2배면 토큰 쌍 4배
- **shape를 맞추는 조건 A** : 밀집 텐서는 각 축 크기가 일정해야 한다 → `[3, 5]`
- **shape를 맞추는 조건 B** : `(m, n) @ (n, p) → (m, p)` — 곱하는 두 차원이 같아야 한다
- **문장 길이 ≠ 임베딩 차원** : 토큰 길이 5, 임베딩 차원 4여도 된다
- **shape 읽기** : `input_ids [4, 12]` = 샘플 4개 × 최종 토큰 길이 12 (특수 토큰·패딩 포함)
- **값 vs shape** : `input_ids`의 값이 `[4, 12]`인 것과 shape가 `[4, 12]`인 것은 다르다
- **임베딩** : `[B, L]` → `[B, L, D]` — 축이 하나 늘어난다 (`[4, 12]`, D=768 → `[4, 12, 768]`)
- **패딩 ≠ reshape** : 패딩은 원소가 늘고, reshape는 원소 수가 유지된다
- **배치마다 길이는 달라도 된다** : 이번 `[4, 12]`, 다음 `[4, 20]`이어도 된다
- **`padding=True` + `max_length=128`** : 무조건 128칸이 아니다 — 항상 채우려면 `padding="max_length"`
- **`max_length`만 지정** : 잘라내기를 켜지 않으면 긴 입력이 자동으로 잘리지 않는다
- **선택적 키 처리** : `batch.items()` 순회 또는 `if "token_type_ids" in batch` — 없는 키를 만들지 않는다

</details>
