## 1. 📖 개요

RAG 2일차 강의와 질문에서 다룬 내용을 **청킹과 Tokenizer, Pooling과 정규화,
내적과 코사인 유사도**의 세 가지로 정리한다.

## 2. ✂️ 청킹과 Tokenizer

청킹은 문서를 검색하기 좋은 조각으로 나누는 작업이다. 크기만 맞추다가 조건이나 예외 문장이
끊기면 답변에 필요한 근거를 잃을 수 있다.

### 문자 수와 토큰 수는 다르다

Tokenizer는 텍스트를 토큰으로 나누고, 단어장에 정해진 숫자 ID로 바꾼다.
`input_ids`는 그 ID 목록이다. ID 자체는 중요도나 유사도 점수가 아니라,
모델이 해당 토큰의 입력 임베딩 벡터를 찾을 때 사용하는 번호다.

```text
텍스트 → 토큰으로 분할 → 토큰 ID → 입력 임베딩 벡터 조회
```

모델은 문자 수가 아닌 토큰 수를 기준으로 입력을 처리한다. 같은 문자 수라도 토큰 수는 달라질 수
있으므로, 본문에 E5의 `passage: ` 접두사와 특수 토큰을 포함한 최종 입력 길이를 확인해야 한다.

```python
len(tokenizer("passage: " + text)["input_ids"])
```

이 코드는 **접두사와 본문을 토큰화하고, ID 목록을 꺼내 그 개수를 세는 것**이다.
입력이 한도를 넘어 잘리면 뒤에 있는 중요한 조건을 모델이 읽지 못할 수 있다.

### Recursive 청킹은 경계를 우선한다

```python
splitter = RecursiveCharacterTextSplitter(
    chunk_size=80, chunk_overlap=20, separators=[". ", " ", ""],
    keep_separator="end", strip_whitespace=False
)
```

| 설정 | 의미 |
| --- | --- |
| `chunk_size=80` | 기본 길이 함수인 `len()` 기준으로 청크를 최대 80자로 구성 |
| `separators=[". ", " ", ""]` | 마침표 뒤 공백을 우선하고, 긴 부분은 공백과 문자 순서로 더 분할 |
| `chunk_overlap=20` | 청크 사이에 일부 내용을 겹치도록 설정. 실제 겹침이 정확히 20자라는 보장은 없음 |
| `keep_separator="end"` | 구분자를 앞쪽 조각의 끝에 보존 |
| `strip_whitespace=False` | 청크 앞뒤의 공백과 줄바꿈을 자동 제거하지 않음 |

> 📌 **기억** · 근거를 온전히 담고, 모델이 끝까지 읽을 수 있게 나눈다.
{: .prompt-tip }

## 3. 🧩 Pooling과 정규화

문장 임베딩은 처음 조회한 토큰 벡터를 바로 평균 낸 결과가 아니다.
모델이 문맥을 반영해 처리한 토큰 벡터들을 Pooling해서 만든다.

```text
텍스트 → 토큰 ID → 입력 벡터 조회
→ 모델이 문맥 반영 → Pooling → 문장 벡터
```

### mask로 패딩을 평균에서 제외한다

다음은 계산을 이해하기 위한 가상 벡터다. 마지막 행은 패딩이라고 가정한다.

```python
tokens = np.array([[1., 2.], [3., 0.], [99., 99.]])
mask = np.array([1., 1., 0.])

pooled = (tokens * mask[:, None]).sum(axis=0) / mask.sum()
unit = pooled / np.linalg.norm(pooled)
```

| 코드 | 역할 |
| --- | --- |
| `mask` | 실제 토큰은 1, 패딩은 0으로 표시 |
| `mask[:, None]` | 마스크 모양을 `(3,)`에서 `(3, 1)`로 바꿔 각 행의 모든 성분에 적용 |
| `tokens * mask[:, None]` | 패딩 행을 `[0, 0]`으로 만들어 합계에서 제외 |
| `.sum(axis=0)` | 각 열의 값을 더해 `[4, 2]` 계산 |
| `/ mask.sum()` | 전체 행 수 3이 아닌 실제 토큰 수 2로 나눠 평균 `[2, 1]` 계산 |
| `pooled / np.linalg.norm(pooled)` | 평균 벡터를 자신의 L2 길이로 나눠 길이를 1로 정규화 |

패딩을 그대로 포함한 평균은 약 `[34.33, 33.67]`이다. 패딩을 제외해야 실제 토큰들의 평균인
`[2, 1]`을 얻을 수 있다. 이를 정규화한 벡터는 약 `[0.8944, 0.4472]`다.

> 📌 **기억** · 문맥을 반영한 토큰 벡터에서 패딩을 제외하고 평균을 낸 뒤, 길이를 맞춘다.
{: .prompt-tip }

## 4. 📐 내적과 코사인 유사도

내적은 같은 위치의 성분끼리 곱한 뒤 모두 더한 값이다. 두 벡터의 방향과 길이 영향을 함께 받는다.
코사인 유사도는 **내적을 두 벡터 길이의 곱으로 나눠 방향의 유사성을 비교**한다.

```python
q = np.array([3., 4.])
candidates = np.array([[6., 8.], [4., -3.], [-3., -4.]])

dots = candidates @ q
lengths = np.linalg.norm(candidates, axis=1)
cosines = dots / (lengths * np.linalg.norm(q))
```

`q`의 길이는 5이고, 계산은 다음과 같다.

| 후보 벡터 | 내적 | 벡터 길이 | 코사인 유사도 | 방향 관계 |
| --- | --- | --- | --- | --- |
| `[6, 8]` | 50 | 10 | `50 / (10 × 5) = 1` | 같은 방향 |
| `[4, -3]` | 0 | 5 | `0 / (5 × 5) = 0` | 직각 |
| `[-3, -4]` | -25 | 5 | `-25 / (5 × 5) = -1` | 반대 방향 |

### lengths와 axis의 의미

`lengths`는 후보별 벡터 길이를 담은 배열로, 위 예시에서는 `[10, 5, 5]`다.
벡터의 길이는 성분 개수가 아니라 각 성분을 제곱해 더한 뒤 제곱근을 취한 크기다.

| 설정 | 2차원 배열에서의 계산 |
| --- | --- |
| `axis=1` | 각 행의 값들을 묶어 계산. 후보가 행마다 있으므로 후보별 길이를 얻음 |
| `axis=0` | 각 열의 값들을 묶어 계산 |
| `axis=-1` | 마지막 축을 지정. 현재 2차원 배열에서는 `axis=1`과 같음 |

축 번호는 0부터 시작한다. 2차원 배열은 0과 1, 3차원 배열은 0, 1, 2를 사용할 수 있다.

### 정규화하면 내적이 코사인 유사도가 된다

`q=[3, 4]`와 같은 방향인 두 후보를 비교하면 길이의 영향을 확인할 수 있다.

| 후보 | 길이 | q와의 내적 | 코사인 유사도 |
| --- | --- | --- | --- |
| `[3, 4]` | 5 | 25 | 1 |
| `[6, 8]` | 10 | 50 | 1 |

두 벡터를 모두 길이 1로 정규화하면 내적을 나누는 길이의 곱도 1이므로,
**내적과 코사인 유사도가 같아진다.**

> 📌 **기억** · 정규화하면 내적으로 방향을 비교할 수 있다. 검색 점수는 정답 확률이 아니므로,
> 답변에 필요한 근거가 있는지 원문을 확인한다.
{: .prompt-tip }

## 5. ✅ 핵심 정리

1. **청킹과 Tokenizer**: 문장 경계를 지키면서 최종 입력 토큰 수를 확인한다.
2. **Pooling과 정규화**: 문맥을 반영한 토큰 벡터에서 패딩을 제외하고 평균을 낸 뒤 길이를 맞춘다.
3. **내적과 코사인 유사도**: 정규화된 벡터끼리는 내적으로 방향을 비교할 수 있다.

## 6. 🧠 핵심 기억 카드

<details markdown="1">
<summary><strong>펼쳐서 확인</strong></summary>

- **input_ids**: 토큰 ID 목록. ID는 임베딩 벡터를 찾는 번호다.
- **문자 수와 토큰 수**: 서로 다르며, 모델 입력 한도는 최종 토큰 수로 확인한다.
- **Mean Pooling**: 토큰 벡터들의 평균. 패딩을 합계와 개수에서 모두 제외한다.
- **L2 Norm**: 벡터의 길이. L2 정규화는 그 길이로 나눠 길이를 1로 만드는 것이다.
- **axis=1**: 2차원 배열의 각 행 안에서 계산한다.
- **내적과 코사인**: 내적은 방향과 길이를 반영하고, 코사인은 길이 영향을 제거한다.
- **검색 점수**: 정답 확률이 아니다. 필요한 답이 있는지는 원문으로 확인한다.

</details>
