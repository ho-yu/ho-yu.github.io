## 1. 📖 개요

긴 문서나 큰 데이터를 한 번에 처리하기 어려울 때는 여러 개의 작은 단위로 나눌 수 있다.
이때 나눈 각각의 데이터 조각을 **Chunk(청크)**라고 한다.

```text
전체 데이터
[────────────────────────]

청크로 분할
[ chunk 1 ][ chunk 2 ][ chunk 3 ]
```

> 📌 **이 글의 핵심 질문** · 문서를 어느 정도 크기로 나눠야 의미를 보존하면서도 효율적으로
> 처리할 수 있을까?
{: .prompt-tip }

---

## 2. 💡 Chunk란?

Chunk는 큰 데이터를 **저장·전송·검색·처리하기 쉽도록 나눈 작은 작업 단위**다.
데이터의 종류를 뜻하는 말이 아니라, 큰 대상을 다루는 방식을 나타낸다.

사용하는 분야에 따라 Chunk가 가리키는 단위는 달라진다.

| 분야 | Chunk의 의미 |
| --- | --- |
| 파일 처리 | 큰 파일을 조금씩 읽는 단위 |
| 네트워크 | 데이터를 나눠 전송하는 단위 |
| 데이터 분석 | 대규모 데이터를 나눠 계산하는 단위 |
| LLM·RAG | 긴 문서를 검색하거나 임베딩하기 위해 나눈 텍스트 단위 |

Chunk는 반드시 같은 크기일 필요가 없다. 바이트 수처럼 일정한 크기로 나눌 수도 있고,
문장이나 문단처럼 의미가 이어지는 경계를 기준으로 나눌 수도 있다.

> 💡 **한 줄 정리** · Chunk는 큰 데이터를 다루기 쉽도록 나눈 작은 작업 단위다.
{: .prompt-info }

---

## 3. ⚖️ 좋은 Chunk의 기준

좋은 Chunk는 **검색하기에 충분히 작으면서도, 그것만 읽고 의미를 이해할 수 있어야 한다.**
이를 판단할 때는 다음 기준을 함께 살펴본다.

### 의미가 하나의 Chunk 안에서 완결되는가?

Chunk가 너무 작으면 하나의 설명이 서로 다른 Chunk로 나뉠 수 있다.

```text
chunk 1: 정밀도는 모델이 양성으로 예측한 데이터 중
chunk 2: 실제 양성인 데이터의 비율이다.
```

이렇게 설명이 중간에서 끊기기보다는 하나의 Chunk 안에서 의미가 완결되는 편이 이해하기 쉽다.
따라서 글자 수만 기준으로 자르기보다 제목, 문장, 문단, 표, 코드 블록 같은 의미의 경계를
고려해야 한다.

### 불필요한 내용까지 포함하지 않는가?

Chunk가 너무 크면 질문과 관계없는 내용까지 함께 검색될 수 있다.

```text
큰 chunk
정밀도 설명 + 재현율 설명 + 데이터 전처리 + 모델 학습 코드
```

정밀도만 찾고 싶어도 나머지 내용이 함께 반환된다. 가능하면 하나의 Chunk에는 하나의 중심
주제를 담는 것이 좋다.

### 경계에서 문맥이 끊기지 않는가?

앞뒤 Chunk의 일부를 겹치게 만드는 것을 **Overlap**이라고 한다.

```text
chunk 1: 문장 1 ~ 문장 10
chunk 2: 문장 9 ~ 문장 18
```

이 예제에서는 문장 9~10이 Overlap이다.

- Overlap이 너무 작으면 Chunk 경계에서 문맥이 끊길 수 있다.
- Overlap이 너무 크면 같은 내용이 반복되고 저장량과 처리 비용이 증가할 수 있다.

### 실제 질문에 답할 수 있는가?

숫자로 정한 Chunk 크기만 보고 좋고 나쁨을 결정할 수는 없다. 실제로 사용할 질문을 넣어보고
다음을 확인해야 한다.

1. 정답이 포함된 Chunk가 검색되는가?
2. 검색된 Chunk만으로 질문에 답할 수 있는가?
3. 관련 없는 내용이 지나치게 많이 포함되는가?
4. 설명과 근거, 표와 해설, 코드와 설명이 서로 분리되지 않았는가?
5. 같은 내용이 여러 Chunk에서 불필요하게 반복되는가?

| 확인된 문제 | 조정 방향 |
| --- | --- |
| 필요한 내용이 여러 Chunk로 흩어짐 | Chunk를 키우거나 Overlap을 늘림 |
| 관련 없는 내용까지 함께 검색됨 | Chunk를 더 작게 나눔 |
| 같은 내용이 반복 검색됨 | Overlap을 줄임 |
| 제목과 본문이 분리됨 | Chunk에 제목이나 상위 문맥을 함께 넣음 |
| 코드와 설명이 분리됨 | 코드 블록과 설명을 같은 Chunk에 둠 |

## 4. 👤 사람의 판단과 자동 평가

좋은 Chunk의 최종 기준은 사람이 정해야 한다. 하지만 모든 Chunk를 사람이 직접 나누고 확인해야
한다는 뜻은 아니다.

```text
사람: 좋은 Chunk의 기준과 평가 질문을 정함
  ↓
시스템: 정해진 규칙에 따라 문서를 자동으로 분할
  ↓
평가: 검색 결과, 답변 정확도, 비용 등을 측정
  ↓
사람: 실패 사례를 확인하고 분할 규칙을 조정
```

시스템은 정답이 포함된 Chunk가 검색됐는지, 정답 Chunk가 몇 번째에 나왔는지, 중복이 얼마나
발생했는지 등을 측정할 수 있다. 그러나 설명과 근거가 분리됐는지처럼 의미와 관련된 문제는
사람의 검토가 필요할 수 있다.

> 📌 **정리** · 사람이 좋은 Chunk의 기준을 정하고, 자동 평가로 많은 결과를 측정한 뒤,
> 실패 사례를 다시 사람이 확인하며 개선한다.
{: .prompt-info }

## 5. 🧪 문자열을 Chunk로 나누기

다음 코드는 알파벳 문자열을 `size=5`, `overlap=2`로 나눈다.

```python
docs = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"
overlap = 2
size = 5

if not 0 <= overlap < size:
    raise ValueError("0 <= overlap < size 이어야 합니다")

chunks = []
step = size - overlap

for start in range(0, len(docs), step):
    chunk = docs[start:start + size]
    chunks.append(chunk)

    # 현재 Chunk가 문서 끝까지 포함했다면 종료한다.
    if start + size >= len(docs):
        break

print(chunks)
```

실행 결과:

```text
[
    'ABCDE',
    'DEFGH',
    'GHIJK',
    'JKLMN',
    'MNOPQ',
    'PQRST',
    'STUVW',
    'VWXYZ'
]
```

핵심 계산은 다음과 같다.

```python
step = size - overlap  # 5 - 2 = 3
```

Chunk의 크기는 5지만 앞 Chunk와 2글자씩 겹치므로, 시작 위치는 3칸씩 이동한다.

```text
ABCDE
   DEFGH
      GHIJK
```

처음 작성한 코드처럼 다음 반복문을 사용하면 주의해야 한다.

```python
for doc in docs:
    text = doc
```

`docs`가 문자열이므로 이 반복문의 `doc`에는 전체 문서가 아니라 `"A"`, `"B"`, `"C"`처럼
문자 하나씩 들어간다. 문자열 전체를 일정한 범위로 나누려면 시작 위치를 이동하며 슬라이싱해야
한다.

## 6. 🧩 불완전한 Chunk 처리하기

**불완전한 Chunk**는 마지막에 남은 데이터가 설정한 Chunk 크기보다 작아서, 정해진 크기를
채우지 못한 Chunk다.

```text
ABCDE  → 5개
DEFGH  → 5개
YZ     → 2개
```

불완전하다는 말은 데이터가 잘못됐다는 뜻이 아니라 **지정한 크기보다 작다는 뜻**이다.

### 앞 Chunk에 모두 포함된 경우

```text
앞 Chunk: VWXYZ
마지막:     YZ
```

`YZ`는 이미 `VWXYZ`에 모두 들어 있다. 이때 `VWXYZ` 뒤에 `YZ`를 다시 붙이면 내용이 중복되므로,
마지막 `YZ` Chunk를 만들지 않으면 된다. 위 예제 코드의 `break`가 이 중복을 막는다.

### 앞 Chunk에 없는 새로운 내용이 있는 경우

```text
앞 Chunk:    STUVW
마지막 Chunk:   VWXY
```

`VW`는 겹치는 부분이지만 `XY`는 앞 Chunk에 없는 새로운 내용이다. 따라서 마지막 Chunk 전체를
삭제하면 `XY`를 잃는다. 이 경우에는 다음 방법을 선택할 수 있다.

- 마지막 Chunk인 `VWXY`를 그대로 유지한다.
- 겹치는 `VW`를 제외하고 새로운 `XY`만 앞 Chunk에 붙여 `STUVWXY`로 만든다.
- 마지막 Chunk의 시작 위치를 앞으로 이동해 설정한 크기에 맞춘다.

문서나 RAG에서는 새로운 정보를 잃지 않는 것이 중요하므로, 새로운 내용이 포함된 마지막 Chunk는
유지하는 방법을 먼저 생각할 수 있다.

## 7. 📏 Chunk 크기는 균일해야 할까?

Chunk 크기는 반드시 균일할 필요가 없다. 문서나 RAG에서는 모든 Chunk의 길이를 똑같이 만드는
것보다 **각 Chunk의 의미가 자연스럽게 완결되는지**가 더 중요하다.

```text
Chunk 1: 짧은 정의               → 100자
Chunk 2: 개념에 대한 자세한 설명  → 500자
Chunk 3: 코드와 실행 결과         → 800자
```

다만 크기 차이가 지나치면 문제가 생길 수 있다.

- 너무 작은 Chunk는 문맥이 부족하고 검색 결과가 잘게 흩어질 수 있다.
- 너무 큰 Chunk는 관련 없는 내용까지 포함하고 입력 토큰을 더 사용할 수 있다.
- 모델의 입력 범위를 넘는 Chunk는 처리 과정에서 잘릴 수 있다.

따라서 정확히 같은 크기를 강제하기보다 최소·목표·최대 범위를 정해 조절할 수 있다.

```python
min_size = 200
target_size = 500
max_size = 800
```

```text
너무 짧음 → 다음 또는 이전 Chunk와 병합
적당함   → 그대로 유지
너무 긺   → 문장이나 문단 경계에서 다시 분할
```

> ⚠️ 숫자는 모든 문서에 똑같이 적용하는 정답이 아니다. 문서 구조와 실제 질문을 기준으로
> 결과를 확인하며 조정해야 한다.
{: .prompt-warning }

## 8. ✅ 핵심 정리

- **Chunk**는 큰 데이터를 다루기 쉽도록 나눈 작은 작업 단위다.
- 좋은 Chunk는 검색하기에 충분히 작고, 그 자체만으로 의미를 이해할 수 있어야 한다.
- **Overlap**은 Chunk의 경계에서 문맥이 끊기는 문제를 줄이기 위해 일부 내용을 겹치는 방법이다.
- 마지막 Chunk가 앞 Chunk에 완전히 포함됐다면 중복해서 만들 필요가 없다.
- 마지막 Chunk에 새로운 내용이 있다면 함부로 삭제하면 안 된다.
- Chunk 크기는 균일하지 않아도 되며, 의미 보존과 처리 효율 사이의 균형이 중요하다.
- 사람은 기준과 평가 질문을 정하고, 시스템은 분할과 측정을 자동화할 수 있다.
